# Project Onboarding Policy

This policy describes how an existing open source project joins the React Foundation, and what happens at each step.

The React Foundation is not an umbrella foundation. Projects that join do not become separate legal entities with their own technical charter; they become part of the React Foundation and operate under its existing governance.

## Overview

| Step | What happens | Who is responsible |
|------|--------------|--------------------|
| 1 | Leadership Council approval | Leadership Council |
| 2 | Working Group home identified | Proposing project + Leadership Council |
| 3 | Project Contribution Agreement signed | Contributing organization or individual |
| 4 | Trademark transfer (if applicable) | Contributing organization + Linux Foundation |
| 5 | Contribution checklist completed | Proposing project + Linux Foundation |

Steps happen in this order. A step does not begin until the previous one is complete.

## Step 1: Leadership Council approval

The Leadership Council must approve the project joining the React Foundation before any other step begins.

To start the approval process, email [technical-leadership-council@lists.react.foundation](mailto:technical-leadership-council@lists.react.foundation).

## Step 2: Working Group home

Each project must have a home under an existing Working Group. If no existing Working Group is a fit, a new Working Group must be formed under the Working Group Policy before the project can proceed.

## Step 3: Project Contribution Agreement

The Linux Foundation holds project names, logos, and key accounts (for example, domain names and GitHub organizations) for the benefit of the project community. This is done through a Project Contribution Agreement signed by the project's founding organization or, in some cases, individual.

Once notified of Leadership Council approval, the React Operations team will help the project complete this step.

**Copyright is not transferred.** Contributors keep the copyright in their code. Contributions continue to be made available under the project's open source license.

## Step 4: Trademark

When a project joins, the Linux Foundation takes ownership of the project's trademark and holds it on behalf of the project community.

- **No registration? It still applies.** An organization may have common law trademark rights from its first public use of a name, even without a registration. Unless the name has never been used publicly, the Project Contribution Agreement is signed so the project can claim that date of first use if it ever needs to defend the mark.
- **Continued use.** No license is needed. The contributing organization, and anyone else, may use the name under the [LF Projects trademark policy](https://lfprojects.org/policies/trademark-policy/).
- **Product names.** The project name may not be used as part of a company's product name. Descriptive statements are allowed, for example "ABC Product is based on [Project]" or "built from [Project]". If the project name is currently used in a product name, tell the Linux Foundation during this step.

## Step 5: Contribution checklist

Once the agreement is signed, the project transfers its assets so they are held neutrally:

- [ ] Add `thelinuxfoundation` as an owner of the project's GitHub organization
- [ ] Transfer the Github repo to the React Github Org (if applicable)
- [ ] Transfer domain(s) to the Linux Foundation
- [ ] Accept/adopt code of conduct
- [ ] Enable a security vulnerability reporting process
- [ ] Send an `.svg` of the project logo to [operations@react.foundation](mailto:operations@react.foundation)
- [ ] Update any website footers and/or Github repos to have the following copyright notice:

  > Copyright © React Foundation, a Series of LF Projects, LLC
  >
  > For web site terms of use, trademark policy and other project policies please see [https://lfprojects.org](https://lfprojects.org/).
